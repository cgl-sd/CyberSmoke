# CyberSmoke「烟圈挑战」模式设计与开发规格

> **核心开发原则：先把功能做出来，再逐步打磨视觉、动效、数值和平衡。**
>
> 当前阶段第一优先级不是“做得最漂亮”，而是“玩法闭环完整、功能可运行、数据可保存、关卡可持续扩展、玩家每局有明确目标与反馈”。
>
> 视觉统一以当前确定的 Reference 为准：**真实香烟 + 黑色极简背景 + 白色烟雾 + 少量薄荷青高亮 + 大面积留白**。  
> 第一版只要求风格一致，不要求一次性达到最终美术品质。

---

## 1. 模式定位

### 1.1 模式名称

**烟圈挑战 / Smoke Ring Challenge**

这是 CyberSmoke 的核心可重复游玩模式。

玩家围绕一支“虚拟香烟”完成：

1. 点火
2. 按住吸入 / 蓄力
3. 在合适时机松手
4. 进入吐雾阶段
5. 用手指绘制烟圈轨迹
6. 系统根据烟圈质量评分
7. 获得分数、经验、资源与收集进度
8. 进入下一局 / 下一关

建议时长：

- 普通单局：10～20 秒
- 单关：30 秒～2 分钟
- 一次完整游玩：3～8 分钟
- 无限模式：由玩家自行决定结束时间

---

## 2. 产品原则

### 2.1 最重要原则：先把功能做出来

整个开发顺序必须遵循：

```text
功能闭环
→ 可重复游玩
→ 数据保存
→ 关卡扩展
→ 奖励与成长
→ 留存系统
→ 数值平衡
→ 动效打磨
→ 美术精修
```

第一版不应因为以下内容拖慢核心功能：

- 高精度烟雾粒子
- 复杂 3D 香烟模型
- 大量不同烟款素材
- 高级光影
- 复杂背景
- 完整品牌动画
- 复杂音频系统
- 多余的商城与社交系统

只要第一版能够让玩家：

> **进入 → 点火 → 吸入 → 松手 → 画圈 → 被评分 → 获得奖励 → 再玩一次**

就已经完成核心 MVP。

### 2.2 视觉是反馈，不是信息堆叠

首页不允许重新回到“信息很多、卡片很多、HUD 很乱”的状态。

核心游玩页长期显示的内容最多包括：

- CyberSmoke 标识
- 当前香烟
- 烟雾
- 当前操作提示
- 必要的蓄力反馈
- 当前目标（必要时）
- 底部导航

以下内容默认不常驻：

- 大量货币
- 等级详细数据
- 多个任务
- 技能列表
- 烟蒂数量
- 烟灰炉信息
- 复杂排行榜
- 抽奖入口
- 多重进度条

这些信息应当收进：

- 图鉴
- 我的
- 结算页
- 关卡开始页
- 临时反馈层

# 3. 核心玩法说明

## 3.1 单局完整流程

一局烟圈挑战包含 7 个状态：

```text
READY
↓
IGNITING 点火
↓
INHALE 吸入
↓
RELEASE 松手
↓
DRAW 吐雾 / 画圈
↓
CALCULATING 计算
↓
RESULT 评分结算
```

建议使用统一状态机：

```ts
type GamePhase =
  | 'ready'
  | 'igniting'
  | 'inhale'
  | 'release'
  | 'drawing'
  | 'calculating'
  | 'result'
```

禁止使用大量散乱 Boolean 控制主流程。

---

## 3.2 READY：准备状态

### 页面表现

中央显示：

- 一支真实视觉风格的虚拟香烟
- 少量静态烟雾
- 主提示：“点火”
- 不显示复杂 HUD

### 玩家操作

点击“点火”区域。

### 功能要求

点击后：

- 播放点火动画
- 点燃香烟头
- 可触发短震动
- 进入 `IGNITING`
- 动画完成后进入 `INHALE`

# 5. 吸入 / 蓄力玩法

## 5.1 操作方式

玩家：

> **按住屏幕 → 蓄力不断增加 → 在合适位置松手**

## 5.2 核心原则

禁止设计成：

> 按得越久奖励越高。

因为这会导致玩家每次都按满。

应改为：

> **存在一个最佳蓄力区间。**

例如：

```text
0%               45%       72%               100%
|----------------|=========|-------------------|
LOW               PERFECT                     OVER
```

建议默认区间：

- 0～44：吸入不足
- 45～72：Perfect Zone
- 73～89：过度吸入
- 90～100：Overload

## 5.3 建议参数

```ts
MAX_CHARGE_MS = 2800
PERFECT_MIN = 0.45
PERFECT_MAX = 0.72
```

不同关卡可以动态修改。

## 5.4 蓄力评分

| 区间 | 评分修正 | 表现 |
|---|---:|---|
| 0～25% | ×0.6 | 烟量少 |
| 26～44% | ×0.8 | 普通 |
| 45～72% | ×1.2 | Perfect |
| 73～89% | ×0.9 | 烟雾较浓 |
| 90～100% | ×0.65 | 过量 |

**过量不能直接判失败。**

玩家始终应该可以进入吐雾阶段，只是评分降低。

# 6. 吐雾与烟圈绘制

这是整个模式最重要的玩法。

## 6.1 操作流程

玩家松手后：

1. 香烟产生烟雾
2. 系统打开绘制窗口
3. 玩家在屏幕上画圆
4. 手指松开后结束采样
5. 系统计算烟圈质量
6. 生成视觉烟圈
7. 进入结算

建议绘制时间：

```text
2.0 ～ 3.5 秒
```

---

# 7. 烟圈识别

每次绘制保存触摸轨迹：

```ts
interface Point {
  x: number
  y: number
  t: number
}
```

一次绘制：

```ts
Point[]
```

## 7.1 评分维度

烟圈至少计算：

1. 闭合度
2. 圆度
3. 尺寸
4. 流畅度
5. 绘制速度
6. 中心稳定度

## 7.2 闭合度

取：

```text
首点与尾点距离
÷
烟圈估算直径
```

越小越好。

示例：

```ts
closureScore =
  clamp(1 - endDistance / diameter, 0, 1)
```

## 7.3 圆度

第一版使用简单算法即可：

1. 求轨迹中心点
2. 求每个轨迹点到中心点距离
3. 求平均半径
4. 计算每个半径与平均半径差异
5. 差异越小，圆度越高

伪代码：

```ts
meanRadius =
  average(distance(point, center))

variance =
  average(abs(distance(point, center) - meanRadius))

roundness =
  clamp(1 - variance / meanRadius, 0, 1)
```

第一版不需要机器学习。

## 7.4 流畅度

根据：

- 相邻轨迹角度突变
- 手指停顿
- 轨迹回退
- 多次乱画

产生 penalty。

## 7.5 尺寸

根据烟圈相对于屏幕的直径计算：

- 太小：扣分
- 太大：扣分
- 合理：加分

默认最佳直径：

```text
屏幕宽度的 30% ～ 65%
```

---

# 8. 综合评分

建议：

```text
总评分 =
闭合度 × 30
+ 圆度 × 35
+ 流畅度 × 20
+ 尺寸 × 10
+ 时间 × 5
```

满分：

```text
100
```

然后乘以蓄力修正。

## 8.1 评级

| 分数 | 等级 |
|---:|---|
| 0～39 | C |
| 40～59 | B |
| 60～74 | A |
| 75～89 | S |
| 90～97 | PERFECT |
| 98～100 | LEGEND |

# 11. Combo

连续达到 A 以上增加连击：

```text
A / S / PERFECT / LEGEND
→ Combo +1
```

低于 A：

```text
Combo 清零
```

Combo 加成：

| Combo | 加成 |
|---:|---:|
| 1 | ×1.00 |
| 2 | ×1.05 |
| 3 | ×1.10 |
| 5 | ×1.20 |
| 10 | ×1.35 |
| 20 | ×1.50 |

最高建议：

```text
×2.0
```

# 46. 最终开发准则

整个项目在当前阶段只遵守一个优先级：

> # 先把功能做出来。

如果一个功能：

- 不够漂亮
- 动画不够精致
- 烟雾还不够真实

但已经：

- 可以操作
- 可以评分
- 可以获得奖励
- 可以进入下一关
- 可以保存进度
- 可以持续玩

那么它应该先进入版本。

反过来：

如果一个页面：

- 很漂亮
- 烟雾很真实
- 动画很高级

但玩家：

```text
玩不了
没有目标
没有成长
没有下一关
没有奖励
```

则该版本仍然不算完成。

# 48. Reference 使用原则

当前选定的界面图只作为整个游戏的**视觉 Reference**，不是要求程序 1:1 复制图片。

程序实现优先顺序：

```text
1. 交互正确
2. 状态正确
3. 评分正确
4. 奖励正确
5. 关卡正确
6. 存档正确
7. 信息层级接近 Reference
8. 颜色接近 Reference
9. 烟雾效果逐步优化
10. 最后再精修视觉
```

第一版必须优先确保“能玩”，而不是为了追求视觉一致性延迟核心玩法开发。
