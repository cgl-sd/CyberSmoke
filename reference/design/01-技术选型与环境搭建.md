# 技术选型与环境搭建（讨论记录）

> 2026-09-12 与 ZCode 讨论确定的项目开发基础方案。

## 一、语言与框架选择

**结论：微信小程序原生框架 + TypeScript。**

原生小程序技术栈四件套：

- WXML —— 页面结构（类似 HTML）
- WXSS —— 样式（类似 CSS）
- TypeScript / JavaScript —— 逻辑
- JSON —— 页面与全局配置

选原生的理由：

1. 官方模板直接支持 TS，微信开发者工具内置编译插件（`useCompilerPlugins: ["typescript"]`），无需自搭构建链
2. 对 AI 辅助编码最友好：LLM 见过的原生小程序代码最多，报错好排查
3. 跨端框架（Taro / uni-app）只在需要一套代码跑 H5、App、其他小程序时才有价值，初期徒增复杂度

## 二、本地开发环境

| 组件 | 要求 | 本机状态（2026-09-12） |
| --- | --- | --- |
| Node.js | ≥ 18 | v22.23.2 ✅ |
| npm | 随 Node | 10.9.8 ✅ |
| 微信开发者工具 | 必须 | 已安装 `/Applications/wechatwebdevtools.app` ✅ |
| AppID | 测试号即可 | 游客模式 `touristappid` ✅ |

- 正式 AppID 注册：mp.weixin.qq.com（个人主体免费）；本项目用测试号开发
- 编辑器：外部编辑器（VS Code / Cursor / ZCode）写码 + 开发者工具预览调试

## 三、调试手段

1. **模拟器**：开发者工具内置，Chrome 风格调试面板（Console / Sources 断点 / Network / WXML 审查），日常 90% 在这里
2. **真机预览**：扫码在手机上运行，验真实交互
3. **真机调试**：手机跑、电脑看日志，查真机特有问题
4. **命令行 CLI**：`/Applications/wechatwebdevtools.app/Contents/MacOS/cli`，可脚本化打开/预览/上传，配合 AI 流程

## 四、已知的坑

- 请求后端必须 HTTPS 且在小程序后台配白名单；本地开发在开发者工具勾选「不校验合法域名」（本项目已在 `project.config.json` 中设 `urlCheck: false`）
- 不想自建服务器可用微信云开发（云函数 + 云数据库），个人项目省去备案
- 合规：个人主体没有「游戏」类目可选；「模拟吸烟」题材有审核风险，详见玩法设计文档
